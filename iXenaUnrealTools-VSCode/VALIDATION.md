## 本版重点覆盖

### 初始化与分类

- 插件初始化仅保存选择并打开固定仓库地址，不创建插件目录、不运行构建、不修改 `.uproject`。
- MCP 初始化依次校验 IP、端口和路径；取消保留之前配置，合法输入生成单个端点。
- 初始化与构建/通讯忙碌状态互斥；只读的“检查连接”不被普通 UBT 构建任务阻断，异常退出释放操作状态。
- 通讯树按四组组织，具有稳定节点 ID，统一初始化动作不会在组内重复。
- VSIX 排除 UE 源码和已移除的自动安装器；手动源码/脚本由独立组件交付。

### 多语言

- 自动语言选择覆盖中文区域、英文及未提供翻译时的英文回退；显式设置可覆盖自动选择。
- 运行时目录的占位符数量保持一致；路径、技术名称和包含花括号的用户值不被再次解析。
- 侧栏、状态栏和上次构建结果可在切换语言后重新显示。
- 类向导显示英文时，生成的 C++ 标识符和中文头文件注释保持正确。
- 描述文件和依赖面板保留未提交输入；性能面板保留历史样本，切换语言不触发额外业务动作。
- 静态 `package.nls` 与动态语言设置分别验证，不能把动态设置声称为 VSCode 静态菜单的即时切换。
- UE 原生语言实现与中文命令帮助资源完成静态审查；实际字体、ToolMenus 合并和窗口语言切换仍需 Editor 实机检查。

### 协议与构建结果

- 临时文件 IPC 测试使用真实文件读写和模拟 UE 响应，覆盖实例识别、请求关联、日志分块和结果解析。
- 协议 1 仅明确接受 Bridge 0.5.0/0.6.0/0.6.1/0.6.2；未知版本、错误协议、身份或 token 被拒绝。
- 失败、超时或结果未知不自动重发，也不回退为另一轮 UBT 构建。
- 连接成功以 UE ping 回应为准，失败会显示明确状态；可查看旧心跳及项目/引擎/版本不匹配诊断。Live Coding 能力单独判断。引擎原生日志按原文保留，可识别诊断进入独立 Problems。
- MCP 使用受控 HTTP/SSE 响应测试握手、分页、工具发现、错误和结果；这些模拟不证明真实 UE 服务已经连接。

### 保留功能

- 原有多根工作区读取、任务准备、终端复用/取消编排、引擎路径、UHT、资源分栏、类文件创建、源文件切换、描述文件及依赖编辑继续做回归。
- 发布者 ID 变更覆盖 URI 路由和任务所属标识；旧版安装与新版本的实际共存/迁移仍需本机检查。
- 独立 Tools 脚本检查关注参数、空输出目录、实际 UAT 退出码和完整产物，不将模拟 UAT 成功当作 UE 编译通过。
- `FCompileOutput` 参数重命名为 `InCompileLogPath` 的修复属于源码审查，不是 MSVC/UE 实编译证明。

## 明确的验证边界

1. 当前环境没有 UE、MSVC 或 Xcode，没有生成并验证可加载的 Win64 DLL / Mac dylib / Linux so。
2. 真实 VSCode Extension Host/GUI 需要可用显示与 IPC 服务；DOM 测试不等于原生 Webview 的视觉验收，CLI 安装也不等于扩展激活。
3. Windows Explorer 注册、Windows 终端 Ctrl+C/进程树，以及 macOS 加载需要相应系统检查。
4. 未建立所有旧 UE5 版本的实编译矩阵。源码中的兼容保护仍需所选引擎验证。
5. UE GLog 不保证收到独立 Live Coding Console 的全部编译器输出；通信超时也不证明 UE 已取消编译。
6. 指标由 UE 主线程采样，断点、同步编译或忙碌会导致数据暂停；保持最后读数并标记过期是预期行为。
7. 公开仓库内容、Marketplace 上架和 GitHub Release 未在本次交付中发布或确认完成。

## 复验命令

在 VSCode 组件目录执行：

```bash
npm ci
npm test
npm --prefix test/ui ci
npm run test:ui
npm run test:host
npm run package
```

`test:host` 要求有效桌面/显示服务，可用 `IXENA_UNREALTOOLS_TEST_VSCODE` 指定已有 VSCode 可执行文件。独立 UE 构建命令见 README 和兄弟组件 Tools。

## 本机最小验收

1. 停用旧 `ixena-local` 版并安装新 VSIX，确认只有一套按钮。验证旧系统菜单移除和新菜单注册。
2. 打开 `D:\Develop\UnrealEngine\UE5Test\UE5Test.uproject` 所属工作区，确认选定引擎为期望目录。
3. 点初始化，插件方式应打开正确仓库且没有后台安装任务；MCP 方式应出现 IP/端口/路径，并验证取消不改配置。
4. 使用独立 Tools 手动构建插件，确认输出持续出现且 UAT 退出成功；完整复制产物到一个插件目录，启用并重开 Editor。
5. 检查连接的项目、引擎和 PID。打开原生 iXena 面板、查询命令、查看监测；命中断点后应标记数据暂停。
6. 在中文和英文间切换动态界面；在描述编辑器保留未提交输入再切换，确认草稿未丢失。静态菜单通过 VSCode 显示语言验证。
7. Windows 开启 Live Coding 后修改现有函数，核对 UE 实际结果；制造并恢复一个可控错误，核对失败日志和可获得诊断。
8. 在测试分支创建新类、补齐依赖并完整构建。macOS/Linux 单独验证源码构建、面板与完整编译入口。
